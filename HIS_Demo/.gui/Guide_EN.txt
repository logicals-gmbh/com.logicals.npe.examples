HIS PACKAGING LINE — PYTHON GUI v1.2
30 October 2026

START
Double-click START_GUI.cmd. The application always starts in local demo mode.
Alternatively, run python his_gui.py from this folder.
Python 3.10+ with Tkinter is required. The launcher also recognizes the existing
development installation at C:\LC3ENV\tools\python-3.11.4-win64\python.exe.

LOCAL PREVIEW
Press Start. A carton moves into the station, is sealed and moves out.
Fast cycle, carton jam, enable, stop, reset and simulated emergency stop are
available. This mode uses a local preview model, not a PLC. It starts enabled
and ready for immediate demonstration. Normal/fast cycles take about 8/4.5 s.
The PLC mode uses actual read values instead of this model.

OPC UA DEPENDENCY
Using the same Python installation, run:
python -m pip install -r requirements.txt
The required package is opcua==0.98.13 (python-opcua). It was already installed
on the development machine. No additional graphics libraries are required.

RTS MAX CONNECTION
1. Expose the required program variables through RTS Max OPC UA. Obtain the
   actual endpoint, user permissions and authentication requirements.
2. Open Connection & Node IDs. localhost:4840 has now been confirmed
   as the local RTS Max endpoint with anonymous access.
3. Configure anonymous access or username/password. Passwords stay in memory
   and are not saved in config.json. HIS_OPCUA_PASSWORD is also supported.
4. If required, configure the matching Security string and absolute certificate
   paths, for example Basic256Sha256,SignAndEncrypt,client.der,client-key.pem,server.der.
   Configure mutual certificate trust as required by the server.
   An empty string means SecurityPolicy None; no automatic downgrade is used.
5. Save, then select Connect OPC UA in the main window.
6. Reopen settings, choose Browse server and Load Objects. Expand the
   hierarchy, select a Variable node, select its logical signal and assign it.
   Exact Node-IDs can also be entered manually in the Node-IDs tab.
7. Save and reconnect. Saving configuration disconnects an existing session.
8. Map at least state, count and permit for the visualization, then add the
   diagnostic and control signals. The initial connection is read-only.
9. For control, ensure the nodes are writable on the server and switch
   PLC controls to ENABLED. State and Permit must be mapped. Control is disabled
   again on each new connection.

No Node-ID is inferred from a variable name. Actual namespace indexes and
identifiers are server-specific. The GUI does not configure the RTS Max server.

sim_estop       Sim_EStopReleased (RTS Max simulation program only)

Only the listed Boolean control variables can be written. State, counter,
permission, diagnostics and safe outputs are never written.
Start/Stop/Reset/Acknowledge use 250-ms pulses. The current 10-ms PLC task is
appropriate for these pulses. The default 100-ms GUI polling interval is
independent of the PLC task. Existing TRUE pulse signals are not retriggered.
Each control requires a distinct Node-ID. Boolean server types are checked.

For the Sim_EStopReleased program, explicitly enable RTS Max simulation program
in settings and map sim_estop. FALSE simulates pressed; TRUE simulates released.
Then apply Safety Reset and a new Start. Leave this option disabled for the
physical demo box and operate its actual emergency-stop button.

CONNECTION LOSS AND DISPLAY
Errors stop live animation and disable controls. Last counter/diagnostic
values may remain visible, but the display indicates OFFLINE instead of a
current safety permission. There is no silent fallback to the local model.
Reconnect is manual. Bad StatusCodes are not displayed as valid zero/FALSE.
Freshness is based on successful reads; a server returning internally stale
process data with Good quality cannot be detected by this mechanism.
Carton position is interpolated from phase and time, not measured.

The GUI Stop is an OPC UA process command, not a safety emergency stop.
Neither this GUI nor OPC UA provides a safety function. A disconnection between
the rising and falling edge of a pulse may prevent its reset. An error message
then requests checking the PLC signal. PLC-side communication-loss handling
remains the responsibility of the PLC application.
